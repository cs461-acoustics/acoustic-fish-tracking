Definition of Done
A change must pass the following checks before merging into our main branch:
Tests : Unit and integration tests pass successfully, enforced via GitHub actions CI created by the Quality Owner in Sprint 2
Review : A formal peer review approval from at least one teammate, enforced by a GitHub Branch Protection Rule in Sprint 1 by all team members
Docs Updated : README and relevant docstrings updated, manually enforced by the Documentation Owner
AI Usage: proper annotation and documentation of AI incorporation and contributions, manually enforced by the AI Coordinator
Lint & Data : No hardcoded personal data or secrets, and proper code formatting, enforced through a Hook and CI job created by the Quality Owner in Sprint 2
CI Gates: All automated checks pass cleanly
Contribution Norm
To ensure equitable distribution of work and consistent progress towards the sprint goals:
The Floor: Every team member owns at least one piece of accepted work per sprint
Where Work/Documentation lives
Code, tests, workflows, README: GitHub Repository
Planning and tasks: Jira Projects Board
Training data: TBD
Documentation: Shared Google Drive
What accepted means
Code/Models: Satisfies the Definition of Done requirements and is merged into main
Tasks: Relevant task is completed by assigned member, reviewed by team lead, and marked done on the task board
Datasets/Data processing: Data is cleaned, documented, and reviewed/verified by Team Members.
Documentation/Reports: Documentation is reviewed by the Documentation Owner, and reports are reviewed by the entire team
